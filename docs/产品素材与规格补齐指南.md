## §3 素材规则（必须遵守）

### 图片来源

1. **首选：业主提供**（官方产品手册 PDF / 实拍图）。若业主给了文件，放到 `assets/inbox/` 对应目录并告知维护者
2. 次选：公司官方渠道（官网/官方公众号/官方 YouTube）公开发布图
3. **禁止**：从同行/竞品官网盗图；带第三方水印的图；AI 生成图冒充实拍

### 图片规格

- 每个产品 **1 张主图（必需）+ 1~3 张细节图（可选）**
- 比例：主图 4:3（建议 1600×1200），细节图方形或 4:3，单张 ≤2MB，PNG/JPG/WebP
- 上传方式：后台「产品管理 → 编辑产品 → 图片上传」（第一张自动为主图，可拖动排序）

### 规格描述规则（真实性红线）

1. **所有数值必须有官方来源**（产品手册/ datasheet / 业主确认稿），并在工作记录里注明来源文件与页码
2. 找不到确切数值的参数：**删除该条目**，禁止保留推测值（海外客户按规格询价，虚标=商务风险）
3. 单位统一国际制（kg / mm / m / m/s / h / V / Ah），英文单位写法与官方 datasheet 一致
4. 中英文必须语义一致（英文是主语言，先写英文再译中文，禁止机翻腔）

### 数据结构（后台「产品管理 → 编辑」对应字段）

- `quickSpecs`（头部速览，4 条以内）：如 额定负载 / 举升高度 / 导航方式 / 续航
- `specGroups`（规格分组表格）：每组一个主题（基本参数/运动性能/导航定位/电池/安全/环境），组内 label+value 双语
- `features`（特性列表，4~6 条）：一句话卖点，双语
- `description/tagline`：概述，双语
- `specUrl`：规格书 PDF（后台上传，公开可下载）

## §4 网络与环境约束

- 本机网络仅 GitHub 系、npm 镜像可达；**大多数海外图床/官网不可直连**——素材以下载失败的，记录 URL 交给业主人工获取
- 搜到官方 PDF 后可用 `pdftotext`（poppler）或在线转换提取规格表
- 修改产品数据一律走**后台管理界面**（或 API `PUT /api/products/:id`，需 staff token），禁止直接改数据库

## §5 验收标准（每产品逐项）

- [ ] 前台产品详情页主图正常显示（无占位块）
- [ ] quickSpecs ≤4 条、specGroups 每组 ≤8 行，数值均可溯源
- [ ] 英文页面与中文页面展示各自语言，无中英文混杂
- [ ] specUrl 有 PDF 的，点击可下载
- [ ] 前台 `/zh/products/<slug>` 与 `/en/products/<slug>` 人工目检通过

## §6 建议执行顺序

1. 先补 7 款缺图产品的图片（影响前台观感最直接）
2. 再核实 10 款 📝 产品的规格真实性（业主提供手册后逐款替换）
3. 软件类（WCS/IWMS）最后：界面截图 + 功能清单（需业主提供账号截图）
